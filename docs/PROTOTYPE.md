# 画面サンプル

## 開く

`prototype/index.html`を保存してブラウザで開く。単一ファイル、インストール不要、外部通信なし。再読込でデモデータに戻る。スマホとPCで同じ操作を試せる。

表示されるリポジトリの説明、言語、件数、Issue / PR番号、ファイル、ブランチ、CI結果はすべて架空のサンプル。実リポジトリの現在の状態を取得していない。投稿、保存、マージ、既読もメモリ内だけで完結する。入力した内容をGitHubに送らない。

## 試す流れ

1. リポジトリ名で検索し、ForgeDeckを開く。フォルダ・パンくず・ブランチを切り替える。
2. README.md → 編集 → 内容を書き換える → 変更を確認 → 新しいブランチとPRを作る。
3. 元のmainには変更がなく、追加したブランチに変更があることを確認する。
4. ファイル横のメニューから名前変更・削除を提案する。追加から新規テキストやUTF-8ファイルを選ぶ。
5. Deck → レビュー依頼のPR → 差分 → レビュー → マージ候補に移動する体験を試す。
6. Issueから関連PRを開き、CI失敗のチェックを読む。Issue作成・コメントも試す。
7. 受信箱の未読を開き、またはすべて既読にする。

未保存の編集を離れようとすると確認する。自分のPRを承認する操作と、条件を満たしていないPRのマージは無効。マージには対象と方式の確認を挟む。

## 実装されていないこと

Androidアプリ、認証、GitHub API、永続保存、実際のCI判定、実ルールに基づくマージ可否、作業単位の折り畳み集約、ネットワーク由来のエラー・オフライン・SSO対応、push通知。これらはロードマップの後続Issueで扱う。

デモではメインタブの移動と戻るボタンを使う。Androidのシステム戻る操作、OSのファイル選択・キーボードの実機挙動はAndroid版で検証する。

## 確認結果（2026-09-30 JST）

- JavaScript構文確認: `node --check prototype/app.js`
- 単一ファイル生成: `python prototype/build.py`
- DOM操作確認: `prototype/smoke.mjs`をhappy-domで実行。検索/空状態、未保存変更の保持、入力のHTMLエスケープ、元ブランチの不変、新ブランチの変更、未知チェック時のマージ不可、レビューから確認付きマージ、自分のPRの承認不可、Issue作成/コメント、未読状態を検証。

**DOM確認はブラウザの描画確認ではない。** この環境ではテスト用ブラウザの取得とローカルファイル表示に制限があり、320px幅での実描画、文字拡大、OSファイル選択、TalkBack、Android実機は未確認。CSSには小画面向けの折り返し・サイズ変更とライト/ダーク色を実装したが、それだけで実機確認済みとはしない。M0 Issueの該当受入条件は確認が終わるまで未完了にする。

## ソース

`shell.html` / `styles.css` / `app.js` が編集用。`build.py`で配布用`index.html`を生成する。Lucideのアイコンを同梱し、ネットワークからライブラリを読み込まない。ライセンスは`vendor/LICENSE-lucide`。

任意のDOMチェック:

```sh
npm install --prefix /tmp/forgedeck-qa happy-dom --ignore-scripts --no-audit --no-fund
node prototype/smoke.mjs /tmp/forgedeck-qa/node_modules/happy-dom/lib/index.js
```

happy-domは確認作業用であり画面サンプルの実行には不要。AndroidのSDKやビルド環境もこの段階では不要。
