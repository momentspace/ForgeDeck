# ForgeDeck — コンセプトと情報設計

作成日: 2026-09-30 JST。これは設計提案であり、公式 GitHub Android アプリの現在の仕様を調査・評価した資料ではない。起点はユーザーから提示された「リポジトリの場所が分かりにくい」「ファイル操作がしにくい」という課題。

## コンセプト

**どこにいるか、何ができるか、次に何をするかが分かる。**

GitHub の全機能を縮小して並べるのでなく、スマホからリポジトリを開き、ファイルを読み・直し、Issue / PR を進める体験を中心にする。最初の完成目標は GitHub.com に接続する日本語 Android アプリの個人利用向け APK。

## 3つの入り口

| タブ | 最初に見えるもの | 主な操作 |
| --- | --- | --- |
| リポジトリ | 検索、ピン留め、最近使った場所 | リポジトリを開く、ファイルを扱う |
| Deck | 自分の番、待ち、マージ候補 | Issue / PR を横断して次の作業へ入る |
| 受信箱 | レビュー依頼、メンション等の更新 | 更新先を開く、既読にする |

初回の起動先はリポジトリ。最後に使ったタブへの復帰は設定できる。アカウント・外観は右上に集約し、Wiki / Projects のための空タブは置かない。

## リポジトリとファイル

- ピン留めと最近使ったリポジトリを入口にする。owner / repo は全画面で表示。
- リポジトリを開くとファイル一覧へ直行。ブランチとパンくずから現在地が分かる。
- ファイル名のタップは閲覧。隣のメニューは編集・名前変更・削除。長押しを知っていないと使えない操作は作らない。
- フォルダ名・ブランチ名・長い日本語タイトルを折り返し、重要な情報を省略しない。
- Markdown とコードを閲覧。バイナリ・大きなファイルは理由とダウンロード手段を出し、無理に編集しない。
- 編集 → 差分確認 → 保存先ブランチ・コミットメッセージ → PR作成。標準は別ブランチに保存。書込み権限がない場合はその理由を表示する。
- 新規作成、テキストのアップロード、名前変更／移動、削除も同じ変更確認の体験を使う。
- 画面を離れるときに未保存変更を確認。実アプリではローカル下書きも保存し、通信断で入力を失わない。

成功の基準: ピン留めしたリポジトリを起動直後から1タップで開ける。ルートファイルはそこから1タップで開ける。編集中に owner / repo・ブランチ・パスを確認できる。

## Deck: リストを「次の一手」に変える

### 根拠が見える行動分類

| 分類 | 含める例 | 未確認時 |
| --- | --- | --- |
| 自分の番 | 自分へのレビュー依頼、自分の担当Issue、自分のPRのCI失敗・状態確認 | 「未確認」と表示し、確認する行動へ |
| 待ち | 明示的に依頼したレビュー、修正依頼後の対応、手動で待ちに置いたIssue | コメントがあるだけで返答待ちと推定しない |
| マージ候補 | 取得できた必須チェック・レビュー・競合・権限・ルールの条件を満たすPR | 不明な条件があれば候補にしない |

各カードに「なぜここにあるか」を表示する。1件に複数の要因がある場合、先に行動が必要な分類に置き、他の理由も詳細に残す。件数は取得済み範囲と全体を区別する。リポジトリ単位でも絞り込める。

### Issue と PR を「つながった作業」として見る

Issueから関連PRの状態を見る。PRから対応するIssueの受入条件へ戻る。GitHubの明示的な関連情報／closing reference を根拠にする。タイトルが似ているだけでは結び付けない。複数PR、複数Issue、リポジトリを跨ぐ参照、リンクなしも扱う。

同じ作業が担当IssueとCI失敗PRに現れたときは関連性を表示し、実アプリでは作業単位の折り畳み表示も提供する。プロトタイプは関係付きカードまでで、折り畳み集約は未実装。

### 待ちを忘れない

待ちの理由、依頼先、最終更新を表示する。「返答待ち」は手動指定または確認できたレビュー状態による。初期版は通知を送って催促したり、自動でマージしたりしない。AIの利用や外部LLM送信は初期版に必要ない。

## 見た目と操作

静かな面と明確な操作色。ライト／ダーク両方に対応。リポジトリ・フォルダは位置、状態色は行動理由を表す。赤だけで失敗を示さず「CI失敗」と文字でも表示する。

主要操作は48dp以上。本文は16spを基準にし、文字拡大・TalkBack・片手操作で確認する。本文や差分は長くなっても読める。戻ると一覧位置・フィルターを復元する。スマホの下部ナビから主要3機能へ戻れる。

## 状態設計

| 状態 | 実アプリでの体験 |
| --- | --- |
| 読込中 | 骨格表示。古いキャッシュがあれば更新時刻付きで表示 |
| 空 | 「リポジトリなし」「該当なし」「対応する項目なし」を区別 |
| オフライン | キャッシュ閲覧と下書き編集。送信は明示的に再実行 |
| 権限不足／SSO | 原因と再認証への導線。見つからないと断定しない |
| 制限・API失敗 | 再試行可能時刻・部分取得を表示。書込みを自動連打しない |
| 更新競合 | 元のSHAと最新状態を比較。下書きを保持して再確認 |
| マージ可否不明 | 「確認中／未確認」。成功や許可と推定しない |

プロトタイプで動作するのはREADMEとPROTOTYPEに列挙したローカル操作のみ。API由来の失敗・オフライン・SSOは設計まで。

## 初期版の範囲

対象: GitHub.com、単一アカウント、本人がアクセスできる個人／Organizationのリポジトリ、日本語、基本的なIssue／PR／ファイル操作、Deck、通知一覧、CI結果の閲覧。

対象外: Wiki、Projects、Enterprise Server、複数アカウント、git cloneやローカルビルド、Actionsの新規実行、任意の自動化、AI要約、ストア公開。制限されたOrganizationやforkへの書込みは認証・権限検証の結果によって別導線にする。
